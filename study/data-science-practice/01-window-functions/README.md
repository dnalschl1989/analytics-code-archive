# 01 — 윈도우 함수: 사용량 감소 고객 선별

**25분 · BigQuery SQL · Grain과 시간 연속성**

## 1. 문제

`customer_monthly_usage(customer_id, month, data_gb, revenue)`에서 2026년 7월 기준 Risk Customer를 추출합니다.

- 2026년 4·5·6·7월 데이터가 모두 존재해야 합니다.
- 매월 사용량이 직전 월보다 감소해야 합니다(총 3번 감소).
- 7월 사용량은 4월 대비 30% 이상 감소해야 합니다.
- 7월 매출은 50,000원 이상이어야 합니다.
- 고객 × 월에 중복 레코드가 있는 고객은 우선 정합성 이슈로 제외합니다.

**질문:** `LAG`가 이전 *달*이 아닌 이전 *행*을 가져온다는 사실이 어떤 오류를 만들까요? 위험 고객과 케어 우선순위 고객은 반드시 같을까요?

## 2. 힌트

`LAG(data_gb) OVER (PARTITION BY customer_id ORDER BY month)`는 이전 행 사용량입니다. 월 누락을 막기 위해 조회 기간을 네 달로 고정하고 `COUNT(*) = 4` **및** `COUNT(DISTINCT month) = 4` 조건을 함께 검사합니다. 이후 `COUNTIF(data_gb < prev_usage) = 3`으로 연속 감소를 판정합니다.

## 3. 모범 풀이

[solution.sql](solution.sql)은 가상 데이터를 내장한 실행 가능한 BigQuery 쿼리입니다.

- A001: 4월 25GB → 7월 11GB, 사용량 56% 감소, 7월 매출 65,000원 → 대상
- A002: 5월 사용량 증가 및 7월 매출 부족 → 제외
- A003: 6월 결측 → 제외
- A004: 5월 중복 및 6월 결측 → 제외

### 구조

1. 4~7월 데이터만 조회
2. `LAG`로 고객별 이전 행 사용량 계산
3. 4개 월의 완전성·유일성 검사
4. 연속 감소 횟수와 감소율·매출 기준 적용

### 정리 과정에서 추가한 설명 — BigQuery 함수와 전제

`solution.sql`은 ZIP의 원본을 그대로 보존했습니다. 아래는 새로 보강한 설명입니다.

- `UNNEST`는 `STRUCT` 배열의 각 원소를 행으로 펼쳐 가상 원천 테이블을 만듭니다.
- Grain은 **고객 × 월당 1행**입니다. 중복·누락을 모두 검출하기 위해 총 행 수와 서로 다른 월 수를 함께 확인합니다. 이 예제에서 중복 제외 범위는 조회한 4~7월입니다.
- `LAG(data_gb)`는 정렬된 이전 행을 반환하고 첫 행은 NULL입니다. 고정한 네 달의 완전성과 유일성이 확보되어야 이전 행을 이전 달로 해석할 수 있습니다. A004는 네 행이 있지만 월은 세 개이므로 탈락합니다.
- `COUNTIF(data_gb < prev_usage)`는 조건이 TRUE인 행만 셉니다. 첫 행의 NULL 비교는 감소로 세지 않으며, 나머지 세 행이 모두 감소해야 합니다.
- `MAX(IF(month = ..., 값, NULL))`는 특정 월의 값을 열로 펼칩니다. 대상 선정에는 이미 유일성 조건이 있으므로 중복 월의 최댓값으로 문제를 숨기지 않습니다.
- `SAFE_DIVIDE(분자, 분모)`는 0으로 나누는 등 계산 오류에 NULL을 반환합니다. 풀이에서는 4월 사용량이 양수라는 조건도 명시합니다.
- `month`는 `YYYY-MM` 문자열이어서 정렬이 달력 순서와 같습니다. 실제 DATE/TIMESTAMP 원천은 타임존과 월 정규화 규칙을 먼저 정해야 합니다.
- 입력 사용량에 NULL이 있으면 필요한 세 번의 감소를 충족하지 못합니다. 조회 월의 중복 고객과 누락 고객을 별도 품질 리포트로 기록하는 것은 운영 단계의 추가 과제입니다.

## 4. 실무 적용 포인트

- 데이터가 없는 월을 0GB 사용으로 임의 대체하지 않습니다.
- 매출은 고객 가치(Value)의 한 지표이고, 사용량 감소는 이탈 위험(Risk)의 신호일 뿐 실제 이탈 확률이 아닙니다.
- 매월 마감 기준·누락률·복수 사용량 레코드의 처리 정책을 명확히 해야 합니다.
- 추가 연습: 감소율 임계값을 20/30/40%로 바꿔 대상 규모와 실제 후속 해지율을 비교해 보세요.
